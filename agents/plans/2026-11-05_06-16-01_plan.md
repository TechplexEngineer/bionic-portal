# Kiosk Attendance Registration Navigation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ensure the kiosk registration flow always returns users to `/attend`, including successful registration and cancellation.

**Architecture:** Keep the existing `/attend/register` route as the kiosk-specific registration flow. Preserve its server-side `/attend` redirect and add a direct Bootstrap link back to `/attend` on the registration page.

**Tech Stack:** SvelteKit, Svelte 5, TypeScript, Vitest, Bootstrap utility classes.

**Spec:** User request: the `/attend` kiosk page must be the return destination after registration, and the register page must have a cancel button returning to `/attend`.

## Global Constraints

- The kiosk flow must use the exact `/attend` destination.
- Keep styling aligned with existing Bootstrap classes and avoid custom CSS.
- Do not alter the separate full student profile route at `/register`.

## Review Focus

- Successful kiosk registration must redirect to `/attend` — covered by the server action test.
- Kiosk registration page must expose a cancel control targeting `/attend` — covered by the markup test.
- Existing validation failures must remain on the registration page — covered by the existing action behavior and focused test suite.
